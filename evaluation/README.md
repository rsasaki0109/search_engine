# v0.1の目標

よく読む技術サイトを横断して、欲しい情報をすぐ見つけられる個人用検索エンジン。

対象候補はPython・SQLite・MDN・PostgreSQL・Gitの公式ドキュメント。`cases.json` に各サイト4問ずつ、実際の調べ物・検索語・期待するURLを固定する。URLは取得前の候補であり、robots.txt・リダイレクト・ページ変更によって見直す。

## 合格基準

- 5サイト・合計500ページを保存できる
- 固定20問の16問以上で期待ページが上位5件に入る
- 500ページ以上の索引で各検索の所要時間が1秒未満
- 保存したサイトをまとめて更新し、失敗ページを再取得できる

## 測定

```sh
python evaluate.py --collect --output evaluation/local-report.json
python evaluate.py --output evaluation/local-report.json
```

`--collect` は公開サイトへ通信し、まず評価対象20ページを1ページずつ取得する。全500ページを集めるコマンドではない。通常はアプリ停止中に実行する。既存の本文・索引は更新するが、削除しない。

未登録の期待ページは `covered: false` として表示し、20問全体の成功数では不合格として数える。検索語だけから結果を作ったり、期待URLをランキングに使ったりしない。検索時間は各問3回の中央値で、API通信やブラウザー描画は含まない。500ページ未満の計測を速度目標の達成とは扱わない。

## 次の作業

1. 評価対象ページを取得し、URL変更や取得失敗を確認する
2. 5サイトの収集範囲と上限を設定し、500ページで測定する
3. 上位5件に入らない問の本文抽出・ランキングを改善する
4. サイト単位の更新と失敗ページの再取得を実装する

現在のクローラーは1回最大30ページ。500ページ対応・一括更新・検索品質目標は未達。CIのテスト成功とv0.1の合格は区別する。

## 初回測定（2026-11-15）

[測定結果](baseline.json)：19ページを保存。MDN CORSのURL移転を確認して期待URLを修正した結果、20問中19問で上位5件に入った。SQLite SELECTのページは2MB上限で取得できなかった。19ページだけの小さな索引での結果なので、500ページでの検索品質・速度の達成は引き続き未検証。
